# 架构说明

Bill 是本地优先的个人记账应用。Android 正式版使用 Java 原生容器和系统 SQLite，界面使用 React + TypeScript，在内置 WebView 中运行。浏览器开发版通过 IndexedDB 保存账本。

## 模块职责

| 模块         | 职责                                               | 主要入口                                                                                                |
| ------------ | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 领域层       | 账户、分类、交易、预算、校验、统计和备份格式       | [`src/domain/`](../src/domain/)                                                                         |
| 数据层       | 事务提交、版本检查、审计、恢复点和存储适配         | [`src/data/`](../src/data/)                                                                             |
| 平台层       | 异步原生请求、文件导入导出、请求超时               | [`src/platform/native.ts`](../src/platform/native.ts)                                                   |
| 界面层       | 表单、流水、统计、设置及保存反馈                   | [`src/ui/`](../src/ui/)                                                                                 |
| Android 容器 | WebView 生命周期、SQLite、系统文件选择器和显示能力 | [`android/app/src/main/java/com/jizhang/repaired/`](../android/app/src/main/java/com/jizhang/repaired/) |
| 数据库迁移   | 按 schema 版本顺序执行的 SQL                       | [`database/migrations/`](../database/migrations/)                                                       |

`createRepository()` 根据是否存在原生桥选择 SQLite 适配器或 IndexedDB 适配器。浏览器实现用于开发与浏览器使用，不代表 Android 数据库测试结果。Android 数据库操作失败时，不自动切换到另一套存储。

## 数据模型

| 实体   | 关键规则                                       |
| ------ | ---------------------------------------------- |
| 账户   | 稳定 ID、名称、整数分的期初余额、归档状态      |
| 分类   | 稳定 ID、收支类型、名称、颜色、归档状态        |
| 交易   | 支出、收入或转账；日期、金额、账户和备注       |
| 月预算 | 按月份保存，只由支出消耗；收入与内部转账不计入 |
| 审计   | 操作 ID、版本、时间、类型和变更前后值          |
| 恢复点 | 保存导入前账本，用于恢复与交换前后状态         |

当前只支持人民币，金额以整数分保存。内部转账关联两个不同账户，不归入收支分类。账本是个人收支模型，不宣称完整复式会计系统；Beancount 导出为交换格式。

## 展示模型、日期与页面生命周期

[`src/ui/view-models.ts`](../src/ui/view-models.ts) 提供无副作用的展示查询：`homeOverview` 汇总今日支出和月预算，`ledgerTransactions` 按日期、类型、分类筛选并稳定排序，`insightOverview` 复用领域分类汇总并附加展示颜色。`periodRange` 和 `movePeriod` 使用本地日历日期计算日、周、月、年区间。金额仍为整数分，统计排除内部转账；这些模型不写账本，写入继续经过现有 Command 和 Repository。

[`current-date.ts`](../src/ui/current-date.ts) 的共享日期 store 通过可注入的时钟、定时器和事件环境工作；[`use-current-date.ts`](../src/ui/use-current-date.ts) 使用 `useSyncExternalStore` 连接 React。导入模块不注册浏览器资源，首次订阅才启动共享的午夜定时器、focus 和 visibilitychange 监听。每次按本地下一个午夜重新计算，文档隐藏时暂停定时，恢复可见、获得焦点或重新订阅时立即校准；同一天不重复通知，最后一个订阅退出时清理资源。

Shell 保留三个页面挂载，用 `hidden` 和传入 Home、Insights 的 `active` 区分活动页。非活动页退出日期订阅，统计页暂停派生查询和环图尺寸观察，恢复时重新测量容器；不会靠卸载页面清空草稿、统计区间、分类筛选或趋势点选。未手动指定的新交易日期跟随当天；手动日期、历史区间和编辑中交易保持原值。保存成功后才重置表单或关闭编辑，失败保留输入。

首页拆为 [`home/`](../src/ui/home/) 下的 Overview、BudgetPanel 和 LedgerPanel；统计的 [`insights/CategoryBreakdown.tsx`](../src/ui/insights/CategoryBreakdown.tsx) 组合环图与分类金额条形图，两者共享分类筛选，月内每日支出趋势仍单独保留。未来日期表示暂无观测值，未设置预算明确显示未设置。设置页的 [`settings/`](../src/ui/settings/) 分别负责备份、账户、分类、历史和文件任务反馈；导入或恢复成功后清空旧历史展示并允许重新读取。

## 容器布局与设计参考

[`src/ui/layout.css`](../src/ui/layout.css) 负责页面组合，组件外观留在 `App.css`。内容上限为 76rem；首页摘要横跨工作区，录入与流水、分类与趋势、设置模块按 DOM 顺序排列。视口至少 64rem 且内容容器至少 60rem 时才采用双列，容器不足或字体放大时回到单列；手机保留底部导航。模块内部使用可换行字段、容器相对字号和稳定的等宽数字排版，容纳长名称与大金额，保留深色和减少动画支持。

本次重构参考 [ftop](https://github.com/Nongfsq/ftop) 的设计方向：清楚的信息层级、按容器容量调整密度、稳定的数字布局，以及展示与平台能力之间的边界。在 Bill 中只落实为上述界面组织与展示模型，不据此宣称未经测量的性能提升。

## 写入与一致性

界面通过 `Repository.dispatch()` 提交领域命令。Repository 校验新的账本状态、生成审计事件，再让适配器提交；提交成功后更新界面状态，失败时保留错误反馈。

持久化提交在同一事务中完成账本投影、审计、版本以及需要更新的恢复点。提交时检查预期版本，版本不一致返回 `CONFLICT`，界面要求重新加载，防止多窗口覆盖彼此的修改。

Android 使用 `SQLiteOpenHelper` 管理数据库生命周期，数据库名为 `bill.db`，当前 schema 版本为 2。外键和数据库约束校验引用与金额等规则，触发器禁止更新或删除审计记录。这些措施用于防止应用误写，不构成对 root 或设备管理员的防篡改保证。

## 迁移与备份

升级保留 `https://app.local/` 来源，以便读取旧版 `ledger.snapshot.v2` 或 v1 分散键。首次初始化校验旧数据后提交迁移，保留旧存储字节；初始化成功后以新数据库为准。旧数据损坏或仅剩旧恢复点时，显示恢复入口，不静默用空账本覆盖。

Bill JSON 包含账本与审计，是完整备份格式；也支持解析旧版 Ledger JSON。已初始化的账本在导入前保存恢复点。导入的来源审计按事件 ID 展平去重，不冒充本机执行过的变更。CSV、Beancount 导出不能代替完整 JSON 备份。

覆盖升级需要相同 applicationId、相同签名和更高 versionCode。正式版标识是 `com.jizhang.repaired`，调试版带 `.debug` 后缀，二者数据受 Android 沙箱隔离。构建及签名操作见[项目 README](../README.md#一条命令构建-apk)。

## 原生边界与当前限制

原生桥开放数据库读取/提交、文件打开/保存和全屏显示等指定能力。数据库任务在串行执行器上运行；文件操作使用 Android 系统文件选择器。WebView 只加载内置本地来源，阻止外部导航与资源请求，应用没有网络权限。

数据库与导出文件目前没有应用层加密；备份需要由使用者妥善保管。同步接口只预留了类型，尚未实现云同步、端到端加密、CRDT、OCR、通知读取或周期账单。卸载或清除应用数据仍可能丢失账本，建议定期导出备份。
